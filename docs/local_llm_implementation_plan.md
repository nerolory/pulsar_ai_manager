# План реализации локального LLM

## Требования
- Локальные LLM должны работать в отдельном Docker контейнере (для Docker режима)
- Проект должен собираться в standalone приложение с установщиком на ПК
- Модели должны быть распределены по типам (very_light, light, medium)
- При несоответствии минимальным требованиям - запретить использование локального LLM

## Архитектура

### Режим 1: Docker (разработка/сервер)
- Отдельный контейнер `local-llm` в docker-compose.yml
- HTTP API для общения с основным бэкендом
- Модели хранятся в volume
- Автоматический выбор модели на основе системных требований контейнера

### Режим 2: Standalone (Electron)
- Локальный LLM запускается как subprocess из Electron main process
- Модели скачиваются в директорию данных пользователя (`userData`)
- Проверка системных требований при установке/запуске
- Автоматический выбор модели на основе железа пользователя
- Использование Node.js child_process для запуска Python скриптов с LLM

## Этапы реализации

### Этап 1: Базовая инфраструктура
1. Создать модуль `backend/app/providers/local_llm.py` - базовый провайдер для локальных LLM
2. Создать конфигурацию моделей в `backend/app/configs/local_models.py`:
   - Список моделей с их характеристиками
   - Минимальные требования для каждой модели
   - Ссылки на скачивание (Hugging Face)
3. Создать модуль скачивания моделей `backend/app/model_downloader.py`:
   - Скачивание моделей из Hugging Face
   - Проверка целостности (хэш)
   - Прогресс скачивания
   - Кэширование в локальной директории

### Этап 2: Docker контейнер
1. Создать `backend/local_llm/Dockerfile`:
   - Базовый образ: python:3.11-slim
   - Установка зависимостей (torch, transformers, accelerate)
   - Volume для моделей
   - HTTP API сервер (FastAPI)
2. Создать `backend/local_llm/main.py`:
   - FastAPI сервер для локального LLM
   - Endpoint `/generate` для генерации текста
   - Endpoint `/health` для проверки здоровья
   - Endpoint `/models` для списка доступных моделей
3. Добавить сервис в `docker-compose.yml`:
   - Сервис `local-llm`
   - Volume для моделей
   - Зависимость от основного бэкенда
4. Интегрировать в основной бэкенд:
   - Добавить `LocalLLMProvider` в `backend/app/providers/`
   - Проверка доступности контейнера через health check
   - Переключение между облачными и локальными моделями

### Этап 3: Standalone режим (Electron)
1. Создать модуль `backend/app/local_llm_standalone.py`:
   - Интеграция с Electron main process
   - Запуск моделей через Node.js child_process
   - Управление ресурсами (RAM, CPU)
2. Обновить `backend/app/system_check.py`:
   - Проверка требований при запуске
   - Автоматический выбор модели на основе железа
   - Предупреждение пользователю при недостаточном железе
3. Создать Electron main process integration:
   - IPC канал для общения с Python процессом
   - Управление жизненным циклом Python процесса
   - Обработка ошибок и крашей
4. Создать установщик (Electron Builder):
   - Включение Python runtime (или проверка наличия)
   - Включение зависимостей для локального LLM
   - Опциональная установка моделей (по выбору пользователя)

   - Fallback на более легкую модель при недостатке ресурсов

### Этап 5: Проверка требований и запрет использования
1. Обновить `backend/app/system_check.py`:
   - Добавить функцию `can_run_model(model_name)` - проверка требований для конкретной модели
   - Добавить функцию `get_recommended_model()` - рекомендация модели на основе железа
2. Обновить `backend/app/providers/local_llm.py`:
   - Проверка требований при инициализации
   - Блокировка использования при несоответствии
   - Логирование причины блокировки
3. Обновить `backend/app/routes/admin.py`:
   - Endpoint для проверки конкретной модели
   - Endpoint для получения рекомендуемой модели
   - Endpoint для скачивания модели

### Этап 6: UI интеграция
1. Обновить фронтенд:
   - Добавить локальные модели в список провайдеров
   - Показывать системные требования для каждой модели
   - Предупреждение при попытке включить неподходящую модель
   - Индикатор скачивания модели
   - Настройка для выбора типа модели (auto/manual)

### Этап 7: Тестирование
1. Тестирование Docker режима:
   - Запуск контейнера
   - Проверка API
   - Проверка скачивания моделей
   - Проверка переключения моделей
2. Тестирование Standalone режима (Electron):
   - Сборка Electron Builder
   - Проверка запуска на разных конфигурациях
   - Проверка скачивания моделей
   - Проверка работы без интернета
   - Проверка IPC коммуникации между Electron и Python

## Зависимости

### Для Docker контейнера
- torch
- transformers
- accelerate
- bitsandbytes (опционально для 4-bit)
- fastapi
- uvicorn

### Для Standalone
- torch (CPU-only или CUDA)
- transformers
- accelerate
- bitsandbytes (опционально)
- psutil (уже есть)

## Форматы моделей
- GGUF (для llama.cpp) - лучший для CPU
- Safetensors (для Transformers) - лучший для GPU
- PyTorch - стандартный формат

## Стратегия скачивания
- По требованию (on-demand)
- С проверкой хэша
- С прогресс-баром
- С возможностью отмены
- С кэшированием

## Обработка ошибок
- Недостаточно RAM - блокировка с сообщением
- Недостаточно диска - блокировка с сообщением
- Нет интернета - блокировка с сообщением
- Ошибка скачивания - повторная попытка
- Ошибка загрузки модели - fallback на облачную модель
